# คนที่ 2 — แอปนิสิต: ดูจักรยานว่าง · สแกน QR ยืม · รหัสล็อก+นับถอยหลัง

**Process:** 2.0 แสดงจักรยานว่าง · 3.0 ยืมจักรยาน (สแกน QR)
**โฟลเดอร์ของคุณ:** `lib/features/borrow/` (`data/` เรียก Supabase · `state/` Provider · `presentation/` หน้าจอ) · เทสต์ที่ `test/features/borrow/`
**สีประจำบทบาทในแผน:** นิสิต = เขียว

คุณทำฝั่ง **นิสิตทั้งหมด** ซึ่งเป็นเส้นหลักของระบบ ตอนยืมไม่มีเจ้าหน้าที่อยู่ด้วย แอปต้องทำให้ผู้ใช้ไม่งง และกฎทุกข้อฐานข้อมูลเป็นคนบังคับให้ แอปแค่แสดงผลและข้อความให้ถูก

อ่านก่อนเริ่ม: `README.md` และ `docs/database.md` โดยเฉพาะหัวข้อ **4.2 `borrow_bike`**, **4.3 `get_my_active_loan`**, **5 รหัสข้อผิดพลาด**

---

## Flow ที่ต้องทำให้ได้ (จากแผน)

1. เปิดแอป ดูว่าคันไหนว่าง
2. เดินไปที่คันนั้น แล้วสแกน QR บนตัวจักรยาน
3. ยืนยันข้อมูลการยืม: ชื่อ รหัสนิสิต วันยืม — **ดึงจากบัญชีที่ล็อกอิน แสดงให้ดูเฉยๆ ห้ามให้นิสิตพิมพ์เอง** (ถ้าพิมพ์ได้ ใครก็ใส่รหัสเพื่อนได้) กำหนดคืนคือ 21.00 น. ของวันนั้น
4. กดยืนยัน → แอปเรียก `borrow_bike` → แสดง **รหัสล็อกล้อ** + เวลานับถอยหลังถึง 21.00 น.
5. ใช้รหัสปลดล็อกแล้วปั่นได้เลย (คืนที่ป้อมรปภ. ซึ่งเป็นงานของคนที่ 3)

## หน้าจอที่ต้องมี

| หน้า | ต้องแสดง/ทำอะไร |
|---|---|
| **หน้าหลักนิสิต** | ถ้ามีรายการยืมค้าง → โชว์การ์ดรายการนั้น (คันไหน, รหัสล็อก, กำหนดคืน, เวลาที่เหลือ) · ถ้าไม่มี → โชว์รายการจักรยานว่าง · ปุ่มสแกน QR · ปุ่มออกจากระบบ |
| **รายการจักรยาน (2.0)** | จำนวนคันที่ว่าง + รายการเลขคัน/จุดจอด/สถานะ (ว่าง/ถูกยืม/ชำรุด) **อัปเดตสด** เมื่อมีคนยืมหรือคืน (Realtime ดู database.md หัวข้อ 11) |
| **สแกน QR** | เปิดกล้อง อ่านค่า QR (ค่าคือเลขคัน) · มีช่องพิมพ์เลขคันเองเป็นทางสำรอง (ใช้ตอนกล้องเสีย และตอนทดสอบบน emulator) |
| **ยืนยันการยืม** | ชื่อ รหัสนิสิต วันที่ เลขคัน กำหนดคืน 21.00 น. · ปุ่มยืนยัน/ยกเลิก (กันกดซ้ำ ระหว่างรอให้ปุ่มเป็น loading) |
| **รหัสล็อก + นับถอยหลัง** | รหัสล็อกตัวใหญ่ชัด · เวลาที่เหลือก่อน 21.00 น. อัปเดตทุกนาที · เปลี่ยนเป็นสถานะ "เกินเวลา" เมื่อเลยกำหนด |

## ใช้ข้อมูลจากฐานข้อมูลส่วนไหน

| ทำอะไร | เรียกอะไร | หมายเหตุ |
|---|---|---|
| ดูรายการจักรยาน | `from('bikes').select(...)` หรือ `.stream(primaryKey: ['bike_no'])` | เลือกคอลัมน์เอง ไม่มีรหัสล็อกอยู่แล้ว |
| ยืม | `rpc('borrow_bike', params: {'p_qr_code': ...})` | คืนรหัสล็อก + `due_at` |
| ดูรายการที่ยืมค้าง | `rpc('get_my_active_loan')` | คืน `null` ถ้าไม่มี · เรียกตอนเปิดแอปทุกครั้ง |
| ข้อมูลตัวเอง | จาก `Student` ที่ session เก็บไว้ (คนที่ 1) | ไม่ต้อง query ซ้ำ |

**กฎสำคัญ**
- **อย่าเก็บรหัสล็อกลงเครื่อง/log/SharedPreferences** ดึงจาก `get_my_active_loan` ทุกครั้งที่จะแสดง
- ปุ่มสแกน/ยืมควรซ่อนหรือปิดเมื่อมีรายการยืมค้างอยู่ (เพื่อ UX) แต่ **อย่าพึ่งแค่การซ่อนปุ่ม** ฐานข้อมูลจะตอบ `already_borrowing` ให้อยู่แล้ว ต้องแสดงข้อความให้ถูก
- เวลาจากเซิร์ฟเวอร์เป็น UTC ต้อง `toLocal()` ก่อนแสดง และคำนวณเวลาที่เหลือจาก `due_at` ไม่ใช่นับถอยหลังจากตัวเลขในเครื่อง (กันนาฬิกาเครื่องเพี้ยน/แอปถูกปิดเปิด)
- ข้อความ error ใช้ฟังก์ชันกลางจาก `core/errors/app_error.dart` (คนที่ 1) ห้ามเขียนข้อความซ้ำเอง

### กรณีที่ต้องรับมือ (ทุกข้อต้องทดสอบ)
| สถานการณ์ | ควรเกิดอะไร |
|---|---|
| ยืมซ้ำทั้งที่มีคันค้าง | ข้อความ `already_borrowing` ไม่ crash |
| สแกนคันที่คนอื่นยืมอยู่ / คันชำรุด | `bike_not_available` |
| QR ที่ไม่ใช่ของระบบ | `bike_not_found` |
| ยืมหลัง 21.00 น. | `after_hours` |
| ล็อกอินแล้วแต่ยังไม่ผูกสิทธิ์ | `not_verified` |
| เน็ตหลุดตอนกดยืม | บอกให้ลองใหม่ และ **เช็กรายการค้างด้วย `get_my_active_loan`** ก่อน เพราะรายการอาจถูกสร้างไปแล้วทั้งที่แอปไม่ได้รับคำตอบ |
| กดยืนยันรัวๆ | ส่งคำขอเดียว (ปุ่มล็อกระหว่างรอ) |
| ปิดแอปแล้วเปิดใหม่ตอนกำลังยืมอยู่ | เห็นรหัสล็อกและเวลานับถอยหลังเหมือนเดิม |
| คนอื่นยืมคันเดียวกันพร้อมกัน | คนที่ช้ากว่าได้ `bike_not_available` |

## ทดสอบบนเครื่อง

- กล้อง/QR: สิทธิ์ CAMERA ตั้งไว้ใน `AndroidManifest.xml` และ iOS `Info.plist` แล้ว ถ้า emulator สแกนยาก ใช้ช่องพิมพ์เลขคัน (`B01` … `B10`) แทน หรือทดสอบสแกนบนมือถือจริง
- บัญชีทดสอบ: `test01@example.com` … `test20@example.com` (รหัสผ่านถามคนที่ 1) นิสิตแต่ละคนยืมได้ทีละ 1 คัน ถ้าต้องล้างรายการเพื่อเริ่มใหม่ ใช้สูตรรีเซ็ตใน database.md หัวข้อ 10
- ต้องการให้ "เกินเวลา" โดยไม่ต้องรอถึง 21.00 น.: ใช้สูตร SQL ย้อน `due_at` ใน database.md หัวข้อ 10
- ฟังก์ชัน `borrow_bike` ห้ามยืมหลัง 21.00 น. ถ้าทดสอบหลังเวลานั้นจะได้ `after_hours` ทุกครั้ง (เป็นพฤติกรรมที่ถูกต้อง)
