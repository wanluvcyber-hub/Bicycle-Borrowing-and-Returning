### A2. โค้ดกลางใน `lib/core/` (เพื่อนทุกคนจะ import ไฟล์เหล่านี้)
ตั้งชื่อไฟล์ตามนี้เพื่อให้ทุกคนเดาที่อยู่ถูก

| ไฟล์ | ต้องมีอะไร |
|---|---|
| `config/env.dart` | อ่าน `SUPABASE_URL`, `SUPABASE_ANON_KEY` จาก `String.fromEnvironment` + เช็กว่ากรอกแล้วหรือยัง |
| `supabase/supabase_client.dart` | ตัวแปร/getter กลางสำหรับ `Supabase.instance.client` ให้ทุกคนใช้ชื่อเดียวกัน |
| `models/student.dart` | คลาส `Student` ฟิลด์ตามตาราง `students` (ไม่ต้องมี `auth_user_id`) + `fromJson` |
| `models/bike.dart` | `Bike` + enum `BikeStatus` (`available/borrowed/broken` + ป้ายไทย) — **ไม่มีรหัสล็อก** |
| `models/loan.dart` | `Loan` (ตาราง `loans`), enum `LoanStatus`, `LoanCondition`, และ `ActiveLoan` (ผลของ `borrow_bike` / `get_my_active_loan` ที่มี `lock_code`) |
| `errors/app_error.dart` | ฟังก์ชันแปลง error เป็นข้อความไทย โดยแปลงรหัสตามตารางใน database.md หัวข้อ 5 (`PostgrestException.message` → ข้อความ) |
| `router/app_router.dart` | เส้นทางทั้งแอป: นิสิต → `/borrow`, ป้อมยาม → `/guard`, ผู้ดูแล → `/admin` และ redirect ตามบทบาท/สถานะล็อกอิน |
| `theme/app_theme.dart` | ธีมกลาง สีประจำบทบาท: นิสิต=เขียว, ป้อมยาม=ส้ม, ผู้ดูแล=เทา |
| `utils/` | ฟังก์ชันจัดรูปแบบเวลา (เช่น 21:00, "เหลือ 2 ชม. 15 นาที") ที่คนที่ 2 และ 4 ต้องใช้เหมือนกัน |

- ค่าสถานะ/ชื่อฟิลด์ใน model ต้องตรง `docs/database.md` หัวข้อ 2 และ 7 ทุกตัวอักษร
- เวลาใน JSON เป็น ISO 8601 UTC → `DateTime.parse(...).toLocal()` ใน `fromJson`
- แต่ละฟีเจอร์ให้ router รับ "รายการเส้นทางของฟีเจอร์" มาประกอบ (เช่น แต่ละฟีเจอร์มีไฟล์ `*_routes.dart` ของตัวเอง) แล้ว `app_router.dart` แค่รวม เพื่อไม่ให้ทุกคนมาแก้ไฟล์เดียวกัน

### A3. `main.dart` + ล็อกอินขั้นต่ำ

## ส่วน B — ล็อกอินและยืนยันหอใน (process 1.0)

**ที่อยู่:** `lib/features/auth/` (`data/` เรียก Supabase · `state/` Provider · `presentation/` หน้าจอ)

### ลำดับการตัดสินใจหลังล็อกอิน (ต้องเป็นแบบนี้)
1. ล็อกอินสำเร็จ → `select` แถวตัวเองจากตาราง `staff` (`user_id = auth.uid`)
   - มีแถว → เป็นเจ้าหน้าที่ ได้ `role` = `guard` หรือ `admin`
2. ไม่มีแถวใน `staff` → เรียก `claim_student_profile()` (database.md 4.1)
   - สำเร็จ → เป็นนิสิต เก็บข้อมูล `Student` ไว้ใน state
   - ได้ `not_in_dorm_list` → ไม่ใช่นิสิตหอใน แสดงหน้า "ไม่พบสิทธิ์" พร้อมปุ่มออกจากระบบ
3. ไม่ได้ล็อกอิน → หน้าล็อกอิน

### งาน
- [x] `SessionProvider` (หรือชื่อที่ทีมตกลง) เก็บ: สถานะ (กำลังโหลด / ยังไม่ล็อกอิน / พร้อมใช้ / ไม่มีสิทธิ์), บทบาท, ข้อมูลนิสิต/เจ้าหน้าที่ และให้ router ฟังเพื่อ redirect
- [x] ฟัง `supabase.auth.onAuthStateChange` เพื่อรู้ตอนล็อกอิน/ออก/เซสชันหมดอายุ (ระวังอย่าโหลดซ้ำทุกครั้งที่ token refresh)
- [x] หน้าล็อกอิน (อีเมล + รหัสผ่านก่อน) แสดง error เป็นข้อความไทย ไม่โชว์ข้อความดิบของระบบ
- [x] ปุ่ม/เมนู "ออกจากระบบ" ที่ทุกฝั่งเรียกใช้ได้ (คนที่ 2, 3 จะใช้)
- [x] ค้างล็อกอินไว้ได้ ปิดแอปเปิดใหม่แล้วไม่ต้องล็อกอินซ้ำ (Supabase เก็บเซสชันให้ แต่ต้องเช็กว่า flow ข้างบนรันซ้ำถูกต้องตอนเปิดแอป)
- [ ] **ตกลงกับทีมเรื่องวิธีล็อกอิน "บัญชีมหาลัย" จริง** (database.md หัวข้อ 12 และ 14 ข้อ 5) อย่าปล่อยโหมดสมัครอีเมลเองโดยไม่ยืนยันอีเมล เพราะใครก็ผูกสิทธิ์แทนคนอื่นได้

## ส่วน C — หน้าผู้ดูแลระบบ (process 7.0)

**ที่อยู่:** `lib/features/admin/` เข้าได้เฉพาะ `role = admin` (router ต้องกันคนอื่นไม่ให้เข้า แต่การป้องกันจริงอยู่ที่ฐานข้อมูลอยู่แล้ว)

| หน้า | ต้องทำอะไร | ใช้ข้อมูล |
|---|---|---|
| นำเข้ารายชื่อหอใน | เลือกไฟล์ CSV → ตรวจ → แสดงตัวอย่าง → นำเข้า → สรุป "เพิ่มกี่ แก้กี่ ผิดกี่ (แถวไหน เพราะอะไร)" | `students` ด้วย `upsert(onConflict: 'student_id')` |
| จัดการจักรยาน | เพิ่ม/แก้จักรยาน (เลขคัน จุดจอด) — เพิ่มแล้วต้องมีแถวใน `bike_locks` ด้วย | `bikes` + `bike_locks` |
| รหัสล็อก | ดู/เปลี่ยนรหัสล็อกรายคัน | `bike_locks` |
| งานซ่อม | รายการคันที่ `broken` พร้อมหมายเหตุ → ปุ่ม "ซ่อมเสร็จ" ตั้งกลับเป็น `available` และล้าง `note` | `bikes` |

**ข้อควรระวัง**
- นำเข้า CSV: ส่งเฉพาะคอลัมน์ `student_id, full_name, building, room, phone, email, semester` **ห้ามส่ง `verified`, `late_count`, `auth_user_id`** ไม่งั้นจะทับสถานะของนิสิตที่ผูกบัญชีไปแล้ว (database.md 4.7)
- ตกลงรูปแบบ CSV กับกองหอพัก (หัวคอลัมน์, encoding UTF-8) แล้วเขียนไว้ในหน้านำเข้า
- การเปลี่ยนเทอม: ทำตามสูตรใน database.md หัวข้อ 10 อย่าลบนิสิตเก่าที่มีประวัติการยืม
- (ทางเลือก) หน้าพิมพ์ QR ของแต่ละคัน — ค่าใน QR คือ `qr_code` ของคันนั้น (คือเลขคัน) ถ้าจะใช้ package สร้าง QR ให้เพิ่มผ่าน PR แยกและแจ้งทีม
