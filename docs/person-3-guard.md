# คนที่ 3 — โปรแกรมป้อมยาม: รับคืน+ตรวจสภาพ · สรุปสถานะทุกคัน · ค้นประวัติ

**Process:** 5.0 รับคืน + ตรวจสภาพ · 6.0 ติดตาม / ค้นหาการยืม
**โฟลเดอร์ของคุณ:** `lib/features/guard/` (`data/` เรียก Supabase · `state/` Provider · `presentation/` หน้าจอ) · เทสต์ที่ `test/features/guard/`
**สีประจำบทบาทในแผน:** ป้อมยาม = ส้ม

คุณทำฝั่ง **เจ้าหน้าที่ป้อมยาม** ตอนคืนป้อมยามเป็นคนยืนยันทุกครั้ง และเป็นคนเดียวที่เห็นภาพรวมว่าคันไหนอยู่ที่ใคร ใครเกินเวลา ต้องอ่านง่ายและกดได้เร็ว (ป้อมยามอาจใช้แท็บเล็ต/มือถือ ผลัดกันหลายคน)

อ่านก่อนเริ่ม: `README.md` และ `docs/database.md` โดยเฉพาะหัวข้อ **3 สิทธิ์**, **4.4 `return_bike`**, **4.5 `mark_overdue_loans`**, **4.7 คำสั่งอ่านข้อมูล**, **10 สูตรทดสอบ**

---

## Flow ขาคืน (จากแผน)

1. นิสิตปั่นมาจอดที่ป้อมยาม
2. ป้อมยามสแกน QR หรือพิมพ์เลขคัน → ระบบแสดงว่า **ใครยืม ยืมตั้งแต่กี่โมง**
3. ป้อมยามตรวจสภาพ แล้วเลือก **ปกติ** หรือ **ชำรุด** (ถ้าชำรุดต้องใส่หมายเหตุ)
4. กด "รับคืน" → เรียก `return_bike` → ระบบบันทึกเวลาคืน และตั้งสถานะจักรยานเป็น "ว่าง" หรือ "ชำรุด"
5. หน้าจอแจ้งผลว่ารับคืนเรียบร้อย (และบอกว่าคืนสายหรือไม่)

## สิ่งที่โปรแกรมป้อมยามต้องแสดง (ตามแผน)

| สิ่งที่ต้องมี | รายละเอียด |
|---|---|
| **ตัวเลขสรุป** | ทั้งหมด / ว่าง / กำลังถูกใช้ / ชำรุด / เกินเวลา |
| **สถานะทุกคัน** | เลขคัน, สถานะ, ใครกำลังใช้ (ชื่อ รหัส ห้อง เบอร์) |
| **เวลา** | ยืมตอนไหน กำหนดคืนตอนไหน คืนจริงตอนไหน |
| **ค้นด้วยรหัสนิสิต** | ประวัติว่ายืมคันไหน ยืม-คืนเมื่อไร คืนสายหรือไม่ |
| **รับคืน** | สแกนหรือพิมพ์เลขคัน, ดูผู้ยืม, ติ๊กผลตรวจ, ยืนยัน |

### หน้าจอที่ควรมี
| หน้า | ทำอะไร |
|---|---|
| **แดชบอร์ด** | ตัวเลขสรุป + รายการทุกคัน (กรองตามสถานะได้) + รายการที่เกินเวลาแยกให้เห็นชัด |
| **รับคืน** | ช่องสแกน/พิมพ์เลขคัน → การ์ดผู้ยืม → เลือก ปกติ/ชำรุด (+หมายเหตุ) → ปุ่มรับคืน |
| **ค้นประวัติ** | ช่องกรอกรหัสนิสิต → รายการประวัติเรียงล่าสุดก่อน แสดงว่าคืนสายหรือไม่ และ `late_count` รวม |

## ใช้ข้อมูลจากฐานข้อมูลส่วนไหน

ป้อมยาม (`role = guard`) **อ่านได้ทุกตาราง** ยกเว้น `staff` ของคนอื่น แต่ **แก้ `bikes`/`loans` ตรงไม่ได้** ต้องผ่านฟังก์ชันเท่านั้น

| ทำอะไร | เรียกอะไร |
|---|---|
| รายการจักรยานทั้งหมด | `from('bikes').select(...)` หรือ `.stream(primaryKey: ['bike_no'])` (อัปเดตสด) |
| รายการที่ยังค้าง พร้อมข้อมูลผู้ยืม | `from('loans').select('*, students(full_name, building, room, phone)').isFilter('returned_at', null)` |
| หาผู้ยืมของคันที่รับคืน | กรอง `loans` ด้วย `bike_no` + `returned_at is null` (ใช้ผลเดียวกับด้านบน) |
| ค้นประวัติ | `from('loans').select().eq('student_id', ...)` เรียง `borrowed_at` ล่าสุดก่อน |
| รับคืน | `rpc('return_bike', params: {'p_bike_no', 'p_condition', 'p_note'})` |
| อัปเดตสถานะ "เกินเวลา" | `rpc('mark_overdue_loans')` — เรียกเมื่อเปิดแดชบอร์ด/กดรีเฟรช |
| ดูรหัสล็อก (ถ้าจำเป็น) | `from('bike_locks').select()` ป้อมยามอ่านได้ |

**กฎสำคัญ**
- **ต้องให้ป้อมยามเห็นผู้ยืมก่อนกดรับคืน** เพื่อกันรับผิดคัน/ผิดคน ไม่ใช่กดรับคืนจากเลขคันอย่างเดียว
- ชำรุด = ต้องมีหมายเหตุ (ฐานข้อมูลตอบ `note_required` ถ้าไม่มี) ควรบังคับที่หน้าจอด้วยเพื่อ UX
- "เกินเวลา" ให้ตัดสินจาก `due_at` เทียบเวลาปัจจุบัน (ใช้ `Loan.effectiveStatus` ถ้าคนที่ 1 ทำไว้ใน model) อย่าพึ่งคอลัมน์ `status` อย่างเดียว เพราะอาจยังไม่ถูกอัปเดต
- คืนสายยังรับคืนได้ ระบบนับ `late_count` ให้เอง (ยังเป็นคำถามค้างของทีมว่าจะระงับสิทธิ์ไหม ดู database.md หัวข้อ 14)
- ข้อความ error ใช้ฟังก์ชันกลางจาก `core/errors/app_error.dart` (คนที่ 1)

### กรณีที่ต้องรับมือ (ทุกข้อต้องทดสอบ)
| สถานการณ์ | ควรเกิดอะไร |
|---|---|
| รับคืนคันที่ไม่มีใครยืม | `no_active_loan` → ข้อความชัดเจน |
| ชำรุดแต่ไม่ใส่หมายเหตุ | ปุ่มกดไม่ได้ / `note_required` |
| คืนสาย | แจ้งผลว่า "คืนสาย" และ `late_count` ของนิสิตเพิ่ม |
| รับคืนชำรุด | คันนั้นขึ้นเป็น "ชำรุด" ในแดชบอร์ดทันที และนิสิตคนนั้นยืมคันใหม่ได้ |
| ค้นรหัสที่ไม่มี | บอกว่า "ไม่พบ" ไม่ใช่หน้าว่างเฉยๆ |
| กดรับคืนรัวๆ | ส่งคำขอเดียว (ล็อกปุ่มระหว่างรอ) · ถ้ามาซ้ำจะได้ `no_active_loan` |
| บัญชีที่ล็อกอินเป็นนิสิตเข้าหน้านี้ | router กันไว้ (คนที่ 1) และฐานข้อมูลตอบ `staff_only` |
