ระบบยืมจักรยานหอใน

นิสิตยืมเองผ่านแอปด้วยการสแกน QR และคืนที่ป้อมรปภ. ซึ่งมีโปรแกรมให้ป้อมรปภ.ใช้ตรวจสอบ

นิสิตหอใน ยืมผ่านแอป เจ้าหน้าที่ป้อมรปภ. รับคืนและตรวจสอบ ผู้ดูแลระบบ ดูแลข้อมูลพื้นฐาน

Flow การยืม-คืน

ตอนยืมไม่มีเจ้าหน้าที่อยู่ด้วย ระบบจึงต้องเช็คสิทธิ์ให้เอง ส่วนตอนคืน ป้อมรปภ.เป็นคนยืนยันทุกครั้ง

ขายืมนิสิตทำเองทั้งหมด

  1. เปิดแอป ดูว่าคันไหนว่าง2.0
  2. เดินไปที่คันนั้น แล้วสแกน QR บนตัวจักรยาน3.0
  3. ยืนยันข้อมูลการยืม: ชื่อ รหัสนิสิต วันยืม (ระบบดึงจากบัญชีให้อัตโนมัติ กำหนดคืนเป็น 21.00 น. ของวันนั้น)
  4. ระบบเช็คว่าเป็นนิสิตหอในจริง และไม่มีคันที่ยืมค้างอยู่ จากนั้นแสดงรหัสล็อกล้อ
  5. ใช้รหัสปลดล็อก แล้วปั่นได้เลย แอปจะนับถอยหลังและเตือนก่อน 21.00 น.4.0

ขาคืนผ่านป้อมรปภ.

  1. นิสิตปั่นมาจอดที่ป้อมรปภ.
  2. ป้อมรปภ.สแกน QR หรือพิมพ์เลขคัน แล้วระบบแสดงว่าใครยืม ยืมตั้งแต่กี่โมง5.0
  3. ป้อมรปภ.ตรวจสภาพ แล้วเลือก ปกติ หรือ ชำรุด (ถ้าชำรุดให้ใส่หมายเหตุ)
  4. กด "รับคืน" ระบบจะบันทึกเวลาคืน และตั้งสถานะจักรยานกลับเป็น "ว่าง" หรือ "ชำรุด"
  5. นิสิตได้รับแจ้งว่าคืนเรียบร้อยแล้ว และรหัสล็อกจะหายไปจากแอป

สิ่งที่โปรแกรมป้อมรปภ.ต้องแสดง

นี่คือรายการข้อมูลที่ต้องมี ยังไม่ใช่หน้าจอ ทั้งหมดอยู่ใน process 5.0 และ 6.0

  • ตัวเลขสรุปจำนวนทั้งหมด / ว่าง / กำลังถูกใช้ / ชำรุด / เกินเวลา
  • สถานะทุกคันเลขคัน, สถานะ, ใครกำลังใช้ (ชื่อ รหัส ห้อง)
  • เวลายืมตอนไหน กำหนดคืนตอนไหน และคืนจริงตอนไหน
  • ค้นหาด้วยรหัสนิสิตประวัติว่ายืมคันไหน ยืมและคืนเมื่อไร คืนสายหรือไม่
  • รับคืนสแกนหรือพิมพ์เลขคัน, ดูผู้ยืม, ติ๊กผลตรวจ แล้วยืนยัน

3.0ยืมจักรยานรับ QR ที่สแกนมา เช็คสิทธิ์ (ยืนยันหอในแล้ว และไม่มีคันที่ยืมค้าง) สร้างรายการยืม ตั้งกำหนดคืน 21.00 น. แล้วส่งรหัสล็อกให้นิสิตอ่าน D2 / เขียน D2, D3

6.0ติดตาม / ค้นหาการยืมแสดงตัวเลขสรุปและสถานะทุกคัน รายการที่เกินเวลา และค้นประวัติด้วยรหัสนิสิตอ่าน D2, D3
7.0จัดการข้อมูลพื้นฐานนำเข้ารายชื่อหอใน (CSV) ทุกเทอม เพิ่มหรือแก้ข้อมูลจักรยาน รหัสล็อก และปิดงานซ่อมเขียน D1, D2

Data Dictionary

ทุกคนต้องใช้ชื่อฟิลด์ชุดเดียวกัน ล็อกตรงนี้ให้ได้ก่อนเริ่มเขียนโค้ด

D1ข้อมูลนิสิตหอใน

  • student_idรหัสนิสิต (PK)
  • full_nameชื่อ-นามสกุล
  • building, roomอาคาร, ห้อง
  • emailอีเมลมหาลัย
  • semesterภาคเรียนที่มีสิทธิ์
  • verifiedยืนยันหอในแล้วหรือยัง
  • late_countจำนวนครั้งที่คืนสาย

D2ข้อมูลจักรยาน

  • bike_noหมายเลขจักรยาน (PK)
  • qr_codeค่าใน QR (เก็บแค่เลขคัน)
  • lock_codeรหัสล็อกล้อ
  • stationจุดจอด
  • statusว่าง / ถูกยืม / ชำรุด
  • noteหมายเหตุความเสียหาย

D3ข้อมูลการยืม-คืน

  • loan_idเลขรายการ (PK)
  • student_idผู้ยืม (FK → D1)
  • bike_noคันที่ยืม (FK → D2)
  • borrowed_atเวลายืม
  • due_atกำหนดคืน (21.00 น.)
  • returned_atเวลาคืนจริง
  • received_byป้อมรปภ.ที่รับคืน
  • conditionผลตรวจ: ปกติ / ชำรุด
  • statusกำลังยืม / เกินเวลา / คืนแล้ว
  • is_lateคืนสายหรือไม่

จุดที่ flow ใหม่ต้องระวัง

พอตัดเจ้าหน้าที่ออกจากขั้นตอนยืม จะมีช่องโหว่เพิ่มขึ้น 4 จุดนี้

  • ห้ามให้นิสิตพิมพ์ชื่อและรหัสเองถ้าให้พิมพ์เอง ใครก็ใส่รหัสเพื่อนได้ ปัญหา "เช็คไม่ได้ว่าเป็นหอในจริงไหม" จะกลับมา ควรดึงข้อมูลจากบัญชีที่ล็อกอินและยืนยันหอในแล้ว (1.0) ให้นิสิตแค่กดยืนยัน
  • รหัสล็อกรั่วทุกคนที่เคยยืมคันนั้นจะรู้รหัส แล้ววันหลังเอาไปปั่นได้โดยไม่ผ่านแอป ควรให้ป้อมรปภ.เปลี่ยนรหัสเป็นระยะ หรือเปลี่ยนทุกครั้งที่รับคืน แล้วอัปเดตในระบบ (ต้องถามว่าทำได้จริงไหม)
  • ไม่มีการตรวจก่อนยืมใช้ผลตรวจตอนรับคืนของคนก่อนหน้าแทน คันที่ขึ้นว่า "ว่าง" คือผ่านป้อมรปภ.มาแล้ว และให้นิสิตกด "แจ้งปัญหา" ได้ใน 5 นาทีแรก จะได้ไม่โดนโทษเรื่องความเสียหายที่ตัวเองไม่ได้ทำ
  • จอดทิ้งโดยไม่ผ่านป้อมรปภ.รายการยืมจะค้างอยู่ พอเลย 21.00 น. ระบบขึ้นสถานะ "เกินเวลา" ทั้งในแอปนิสิตและในโปรแกรมป้อมรปภ. ป้อมรปภ.จึงเห็นทันทีว่าคันไหนยังไม่กลับมา

เริ่มยังไง

เป้าหมายแรกคือทำให้เส้นหลัก สแกนยืม → ได้รหัส → ป้อมรปภ.รับคืน ใช้งานได้ครบก่อน ฟีเจอร์อื่นค่อยต่อทีหลัง

  1. ตรวจ DFD กับ Data Dictionary ด้วยกันทั้งทีม2–3 วันแรก

    ไล่ดู DFD ทีละเส้นว่าตรงกับที่ทุกคนเข้าใจไหม แก้ชื่อฟิลด์ให้ลงตัว แล้วล็อกไว้ ต่อจากนั้นใครจะเปลี่ยนต้องบอกทั้งทีม

  2. กลับไปถามป้อมรปภ.และเจ้าหน้าที่

    ใช้คำถามด้านล่าง คำตอบจะกำหนดว่ากฎในข้อ 3.0, 4.0 และ 5.0 เป็นแบบไหน

  3. เลือกเครื่องมือ + ตั้ง database กลาง

    คนที่ 1 สร้างตาราง D1–D3 ใส่ข้อมูลตัวอย่าง (จักรยาน 10 คัน นิสิต 20 คน) ให้คนอื่นใช้ทดสอบ ถ้าอยากเร็วใช้ Supabase หรือ Firebase ได้

  4. ทำเส้นหลักให้ใช้งานได้ครบ

    คนที่ 2 ทำยืม (3.0) คนที่ 3 ทำรับคืน (5.0) ระหว่างนี้ใช้บัญชีนิสิตจำลองไปก่อน ไม่ต้องรอระบบล็อกอินเสร็จ

  5. ต่อของจริงเข้าไป

    เปลี่ยนจากบัญชีจำลองเป็นล็อกอินและยืนยันหอในจริง (คนที่ 1) เพิ่มระบบแจ้งเตือนและเกินเวลา (คนที่ 4) และเพิ่มหน้าติดตาม/ค้นหา (คนที่ 3)

  6. ทดสอบที่ป้อมรปภ.จริง

    ให้ป้อมรปภ.ลองรับคืนจริงสัก 1–2 คัน แล้วเก็บ feedback กลับมาปรับ ก่อนจะเริ่มทำ UX/UI แบบละเอียด

คำถามที่ต้องถามก่อนล็อกสเปก

  1. ขอรายชื่อนิสิตหอในได้จากใคร เป็นไฟล์แบบไหน และอัปเดตบ่อยแค่ไหน
  2. ป้อมรปภ.มีอุปกรณ์อะไรบ้าง (คอม / แท็บเล็ต / มือถือ) และมีกี่คนผลัดกันเข้ากะ
  3. เปลี่ยนรหัสล็อกล้อได้บ่อยแค่ไหน และใครเป็นคนเปลี่ยน
  4. ถ้ามาคืนหลัง 21.00 น. ป้อมรปภ.ยังรับคืนได้ไหม และคืนสายกี่ครั้งถึงจะโดนระงับสิทธิ์
  5. ถ้าจักรยานชำรุด ใครเป็นคนซ่อม และใครเป็นคนกดให้กลับมาใช้งานได้
